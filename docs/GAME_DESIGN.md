# 没入書庫（仮称）企画書
## ——小説を「読む」から「観測される」へ

対象リポジトリ: novel-game
第一弾収録作品: 『壁打ち――観測社会の密室』

---

## 1. コンセプト

**小説を追体験する没入型テキストゲームのプラットフォーム。**

一冊ごとに専用のUI・演出・ゲームメカニクスを持つ「体験版の書庫」を作る。プレイヤーは本棚（書庫）から一冊を選び、その小説の世界のインターフェースそのものに入り込む。

第一弾『壁打ち』では、プレイヤーは例外事案調査員・灰原透として事件を調査する。ただしこのゲームの本体はストーリーの再現ではない。**原作のテーマ（観測・採点・定型構文）を、プレイヤー自身に操作させること**にある。

### 三本柱

1. **UIが世界観を語る。** 機構パートは数値と記録だらけの監視OS。壁打ちパートは数字が一切ない黒い部屋。説明ではなく、画面の空気の差で思想を伝える。
2. **正解のない選択。** 会話（ラリー）に攻略上の正解を置かない。スコアも好感度も表示しない（表示した瞬間、作中の「貢献度」と同じ毒になるため）。返した球によって、返ってくる球が変わるだけ。
3. **ゲームがプレイヤーを観測する。** 選択の速さ、情動ログの手書き率、ヒント使用――ゲームは裏でプレイヤーを記録し、最後にその帳簿を本人に開示する。そして問う。「この記録を消去しますか」。原作の問いをプレイヤーの手に握らせる。

## 2. プラットフォーム設計（複数小説への拡張）

### アーキテクチャ

エンジン（共通）とシナリオ（作品ごと）を完全に分離する。

```
game/
  index.html            … 起動ページ（書庫）
  css/theme.css         … 共通UI＋作品別モードのテーマ定義
  js/engine.js          … シナリオ実行エンジン（作品非依存）
  js/main.js            … 書庫画面・起動処理
  scenarios/
    kabeuchi_ch1.js     … 『壁打ち』第一部（体験版）
    （ここに新作を追加していく）
  scripts/
    build-single.mjs    … 配布用の単一HTMLを生成
  dist/
    kabeuchi_demo.html  … 1ファイル完結の配布版（生成物）
```

### 新しい小説の追加手順

1. `scenarios/<作品id>.js` を作り、`NG.register({...})` でシナリオを登録する
2. `index.html` に script タグを1行追加する
3. 必要なら `theme.css` に作品専用モード（`mode-xxx`）を追加する

これだけで書庫に新しい本が並ぶ。エンジンには手を入れない。

### シナリオ形式（ノード仕様）

シナリオは「ノード」の集合。各ノードは id で接続される。

| type | 役割 |
|---|---|
| `title` | 表紙カード（作品名・章名） |
| `text` | 地の文・会話。タップで一行ずつ進む |
| `choice` | 選択肢。`reply` で選択後の応答をノード内に書ける（ラリーに使用） |
| `diary` | 自由入力。推奨文が最初から入っており、そのまま提出も書き直しも可能。編集の有無と入力時間を記録 |
| `logview` | 調査ウィジェット。ログの一覧から異常を見つける |
| `testimony` | 証言比較ウィジェット。違和感の正体を選ぶ（誤答はやり直し） |
| `stats` | プレイヤー観測記録の開示。消去／保存の選択 |
| `end` | 終了カード。書庫へ戻る |

共通属性: `mode`（画面テーマ切替）、`fx`（接続演出）、`clear`（画面リセット）、`next`。

作品固有のギミックが必要になったら、ノード type をエンジンに一つ追加する。type は作品をまたいで再利用できる資産になる。

## 3. 没入設計（『壁打ち』の場合）

### 二つのモード

| | 機構モード | 壁打ちモード |
|---|---|---|
| 背景 | 深い藍黒 #060a12 | 完全な黒 #000 |
| 文字 | 冷たい明色＋データシアン | 暖色がかった灰の等幅のみ |
| 常時表示 | ヘッダに「●観測中」が明滅 | 何も表示しない |
| 数値 | 適応値・貢献度・達成率が随所に | 数字を一切出さない |
| 音の想定(将来) | 通知音・機械音 | 無音＋打鍵音のみ |

プレイヤーは最初、情報の豊富な機構モードを「便利」と感じ、途中から「見られている」と感じるようになる。壁打ちモードに入った瞬間の「何もなさ」が解放として体感される――この感覚の反転が本作の没入の核。

### モード遷移

画面全体が一度暗転し、「未登録網に接続しています…」「機構統合端末に再接続しています…」の一行だけが表示される。世界の境界をまたぐ感覚を毎回演出する。

### 情動ログ（本作の中核ギミック）

夜になるたび、プレイヤーは情動ログの提出を求められる。入力欄には**最初から推奨文が入っており、ボタン一つで提出できる**。書き直すのは面倒。この面倒さは意図的な設計である。

終盤、被害者の入力記録（打鍵2回・1.8秒）が明かされた直後、ゲームはプレイヤー自身の手書き率を提示する。ミステリーの解決がそのままプレイヤーへの刺突になる。

### 観測記録の開示と消去

エンディングで、ゲームが記録してきたプレイヤーの行動（プレイ時間・選択回数・平均決断時間・手書き率・ヒント使用）を「例外事案調査報告――対象:あなた」として開示する。

そのうえで選ばせる。**消去するか、保存するか。** 消去を選ぶと、セーブデータを含む全記録が実際に消える。どちらを選んでも正解ではない。原作の最終話と同じく、問いは問いのまま持ち帰らせる。

### 記録倫理

テレメトリはすべて端末内（localStorage）のみ。外部送信は一切しない。「観測」をテーマにしたゲームが本当にプレイヤーを外部観測したら台無しであるため、これは演出上の要請でもある。

## 4. 体験版のスコープ（今回実装分）

- 原作第一部（第一話〜第八話）を30〜45分のプレイに圧縮
- 収録シーン: 起動認証 → 給水塔 → 生活ログ調査（静止時間の発見） → 壁とボール → 証言の構文 → 情動ログ① → 遺品端末 → 管理人の開示 → ヌシの記憶 → 名無しの球（ラリー） → シオの最後の三球 → 観測補正 → 申請者名 → 情動ログ② → 観測記録の開示
- 完全版（第二部・第三部）は体験版の反応を見て設計

## 5. ロードマップ

1. **v0（今回）**: 体験版・単一HTML配布
2. **v1**: 完全版『壁打ち』全三部。打鍵音・環境音、実績なし（意図的に）
3. **v2**: 二作目の小説を書庫に追加し、プラットフォームとして成立させる
4. **v3+**: シナリオをJSON外部化しエディタを用意、他の書き手の作品も収録可能に

## 6. 3D調査パート（レイトン／ダンガンロンパ路線）

テキスト版の反応を受けて、方向性を「一人称3D探索＋会話＋証拠収集」に拡張した（`game3d/`）。

- **構成**: 探索パート（一人称で旧市街を歩き、現場・遺留品を調べる）＋会話パート（タイプライター演出のダイアログ、選択肢）＋証拠記録。ダンガンロンパの「調査→学級裁判」構造のうち、調査パートに相当。将来的に「対決パート」（証拠を突きつける論戦。八重樫会議・律子対決が素材）を追加する。
- **技術**: three.js。アセットは全てプロシージャル生成（建物・給水塔・規制テープ・壁・草・ボール・人物ビルボード）。ビルド後も1ファイル・約500KBで、Unityなしでブラウザ／スマホで動く。
- **演出**: 目的地ビーコン、監視サーチライトの回転、赤色灯の明滅、浮遊塵、歩行の揺れ、WebAudioによる環境音とSE、モード遷移の暗転。壁打ち空間は「暗闇の中を歩くと言葉が浮かび上がる」空間として実装。
- **スケール判断**: この規模（章単位の探索シーン）まではブラウザで十分。フィールドが街一つ以上に拡大し、キャラクターの3Dモデル・モーションが必要になった段階で Unity/Godot への移行を検討する。シナリオデータと設計はそのまま移植可能。

## 7. 技術

- 素のHTML/CSS/JS（ビルド不要・依存ゼロ）。`index.html` をブラウザで開くだけで動く
- 配布は `scripts/build-single.mjs` で生成する1ファイル版（tales等で告知→リンク配布を想定）
- スマホ縦画面最適化・タップ操作前提。`prefers-reduced-motion` 対応
